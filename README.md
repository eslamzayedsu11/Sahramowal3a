# سهرة مولعة 🔥

تطبيق ويب رومانسي راقٍ ومخصص **للمتزوجين فقط (+18)** بتصميم عربي كامل (`RTL`) وهوية بصرية مستوحاة من ألبوم الذكريات الليلي (*Midnight Love-Letter Scrapbook*)، مصمم للعب المشترك من اللابتوب أو الهاتف، مع لوحة تحكم متكاملة سهلة الاستخدام من الجوال.

---

## 1. نبذة عن الموقع والمميزات

- **بوابة عمرية وخصوصية تامة**: شاشة تأكيد +18 عند الزيارة الأولى، ومنع فهرسة محركات البحث (`noindex, nofollow` + `robots.txt`).
- **تخصيص أسماء الشريكين**: إدخال اسمي الزوجين، مع اختيار من يبدأ السهرة وتبادل الأدوار تلقائياً مع كل تحدٍ.
- **3 سهرات متدرجة**:
  - **سهرة الدلع** (`dal3`): همسات دافئة ولمسات ناعمة.
  - **سهرة المتعة والاثارة** (`motaa`): شغف متجدد ولحظات جريئة.
  - **سهرة على آخرنا** (`akher`): ليلة بلا حدود لأقصى درجات القرب.
- **تجربة لعب غامرة**:
  - بطاقات بولارويد قابلة للقلب لقراءة الملاحظة السرية الخلفية.
  - مؤقت دقيق يعتمد على الطابع الزمني المطلق (`endTimestamp`) مع تأثيرات تشويقية في الثواني الأخيرة، ودعم `Screen Wake Lock` لمنع انطفاء الشاشة.
  - مشغل أغاني مدمج لكل تحدٍ مع شريط تقدم، مؤقت، وزر مفضلة.
  - قائمة **«براحتكم»** لتخطي التحدي دون إحراج، تبديله بتحدٍ أخف، أو أخذ استراحة تنفس هادئة.
  - حفظ تلقائي لتقدّم السهرة واستكمالها لاحقاً، مع شاشة تقييم رومانسية في نهاية السهرة.
- **وضع الشموع والمؤثرات الصوتية**: إضاءة دافئة هادئة ومؤثرات مصنّعة عبر Web Audio API مع زر كتم سريع.
- **تطبيق ويب تقدمي (PWA)**: قابل للتثبيت على الهاتف والكمبيوتر ويعمل بسلاسة.

## 4. تشغيل المشروع محلياً

تأكد من تثبيت **Node.js 20** أو أحدث:

```bash
# 1. تثبيت الحزم
npm install

# 2. إنشاء ملف متغيرات البيئة المحلي من النموذج
cp .env.example .env.local
# ثم تأكد من تعبئة القيم داخل .env.local

# 3. تشغيل بيئة التطوير (يعمل على http://localhost:3000)
npm run dev
```

أوامر إضافية مفيدة:

```bash
# فحص أنواع TypeScript
npm run typecheck

# بناء نسخة الإنتاج في مجلد dist/
npm run build

# معاينة نسخة الإنتاج محلياً بعد البناء
npm run preview
```

## 6. إعداد Firebase خطوة بخطوة

1. ادخل إلى [Firebase Console](https://console.firebase.google.com/) وأنشئ مشروعاً جديداً (أو افتح مشروعك الحالي).
2. من القائمة الجانبية اختر **Build ← Firestore Database** واضغط **Create database**.
3. اختر المنطقة الجغرافية الأقرب لك (مثل `europe-west3`).
4. **تنبيه مهم جداً حول وضع التجربة (`Test Mode`)**: إذا اخترت البدء في *Test Mode*، فإن Firebase يضع تاريخ انتهاء صلاحية للقواعد بعد **30 يوماً** ويتوقف الموقع عن القراءة والكتابة فجأة بعد شهر! لذلك فور إنشاء القاعدة انتقل إلى تبويب **Rules** والصق محتوى الملف [`firestore.rules`](./firestore.rules) واضغط **Publish**:

```txt
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if true;
    }
  }
}
```

5. من أيقونة الترس ← **Project Settings** ← قسم **Your apps** أضف تطبيق ويب (`</>`)، وانسخ قيم `firebaseConfig` إلى `.env.local` (وإلى إعدادات Vercel لاحقاً).
6. إذا أنشأت قاعدة البيانات بالاسم الافتراضي `(default)`، اترك `VITE_FIREBASE_DATABASE_ID` فارغاً.

## 7. هيكل بيانات التحديات في Firestore

تُخزَّن جميع التحديات في مجموعة (`Collection`) باسم **`challenges`**. وعند فتح التطبيق لأول مرة مع قاعدة فارغة، يزرع التطبيق تحديات مبدئية تلقائياً.

| الحقل | النوع | الوصف والقيم المقبولة |
| --- | --- | --- |
| `category` | `string` | تصنيف السهرة: `'dal3'` (الدلع) أو `'motaa'` (المتعة والإثارة) أو `'akher'` (على آخرنا) |
| `text` | `string` | نص التحدي الظاهر للاعبين (حتى 2000 حرف) |
| `imageUrl` | `string` | *(اختياري)* رابط صورة التحدي داخل إطار البولارويد |
| `backNote` | `string` | *(اختياري)* ملاحظة سرية تظهر عند قلب البطاقة (حتى 300 حرف) |
| `audioUrl` | `string` | *(اختياري)* رابط مباشر لملف صوتي / أغنية |
| `songTitle` | `string` | *(اختياري)* اسم الأغنية الظاهر في المشغل (حتى 120 حرفاً) |
| `timerMinutes` | `number \| null` | *(اختياري)* مدة المؤقت بالدقائق (يمكن أن يكون كسراً مثل `0.5` لـ 30 ثانية) |
| `heat` | `string` | درجة الجرأة: `'warm'` (دافئ)، `'hot'` (حار)، `'blazing'` (مولع) |
| `order` | `number` | رقم ترتيب ظهور التحدي داخل السهرة |
| `active` | `boolean` | هل التحدي مفعّل (`true`) أم مخفي مؤقتاً (`false`) |
| `createdAt` | `number` | طابع زمني للإنشاء (`Date.now()`) |

> **ملاحظة تقنية:** استعلام Firestore يستخدم فلتر حقل واحد (`where('category', 'in', ...)`) مع الفرز داخل المتصفح، لذا **لا يتطلب إنشاء أي Composite Indexes** في Firebase.

## 8. رفع الصور (`ImgBB` + `Freeimage.host`)

عند إضافة أو تعديل تحدٍ من لوحة التحكم واختيار صورة من جهازك:
1. يقوم التطبيق أولاً برفع الصورة عبر **ImgBB** باستخدام `VITE_IMGBB_API_KEY`.
2. في حال تعذر الوصول إلى ImgBB أو فشل الرفع، ينتقل التطبيق تلقائياً إلى **Freeimage.host** كخيار احتياطي باستخدام `VITE_FREEIMAGE_API_KEY`.
3. يمكنك أيضاً لصق أي رابط صورة مباشر (`https://...`) يدوياً في الحقل المخصص دون الحاجة للرفع.

---

## 9. رفع الأغاني أو المقاطع الصوتية على Cloudinary

لإرفاق أغنية بتحدٍ معين:
1. أنشئ حساباً مجانياً على [Cloudinary](https://cloudinary.com/) وافتح **Media Library**.
2. ارفع ملف الصوت (مثل `.mp3` أو `.m4a` أو `.ogg`).
3. بعد الرفع، اضغط على أيقونة **Copy URL** لنسخ الرابط المباشر (يبدو عادةً هكذا: `https://res.cloudinary.com/<cloud-name>/video/upload/v123456/<filename>.mp3`).
4. الصق الرابط كما هو تماماً في حقل **«رابط الأغنية»** داخل لوحة التحكم واكتب اسم الأغنية في حقل **«اسم الأغنية»**.

## 10. الدخول للوحة التحكم

للحفاظ على بساطة واجهة اللعب وإبقاء لوحة الإدارة مخفية عن الظهور المباشر:
1. من **الصفحة الرئيسية**، اضغط **3 ضغطات متتالية سريعة** على شعار **«سهرة مولعة 🔥»** في أعلى الصفحة.
2. ستفتح لك **لوحة التحكم** (مصممة لتعمل بأريحية تامة من شاشة الجوال أولاً).
3. من داخلها يمكنك إضافة التحديات، رفع الصور، إرفاق روابط الأغاني، إعادة الترتيب، تعطيل/تفعيل أي تحدٍ، أو استيراد مجموعة تحديات دفعة واحدة.

## 12. النشر على Vercel خطوة بخطوة

1. ارفع المشروع على مستودع **GitHub** خاص (*Private Repository*) — وتأكد أن ملف `.env.local` غير مرفوع (ملف `.gitignore` يمنعه تلقائياً).
2. ادخل إلى [Vercel](https://vercel.com/) واضغط **Add New ← Project** واختر مستودعك.
3. تأكد من الإعدادات التالية (يكتشفها Vercel تلقائياً من `vercel.json`):
   - **Framework Preset**: `Vite`
   - **Build Command**: `npm run build`
   - **Output Directory**: `dist`
4. افتح قسم **Environment Variables** وأضف جميع المتغيرات الموجودة في `.env.example` (خاصةً متغيرات `VITE_FIREBASE_*` ومتغيرات الصور).
5. اضغط **Deploy** وانتظر اكتمال البناء.

> **تنبيه مهم:** يتم حقن متغيرات `VITE_*` داخل الملفات أثناء عملية البناء (`npm run build`). لذلك عند **إضافة أو تعديل أي متغير بيئة لاحقاً في Vercel**، يجب الدخول إلى تبويب **Deployments** والضغط على **Redeploy** لكي تنعكس القيم الجديدة على الموقع.

## حل المشاكل الشائعة

- **تظهر شاشة «إعداد متغيرات البيئة مطلوب»**:
  تأكد من إضافة كافة متغيرات `VITE_FIREBASE_*` الستة الإلزامية بنفس الأسماء تماماً في Vercel (أو `.env.local` محلياً)، ثم قم بعمل **Redeploy**.
- **التحديات لا تُحفظ أو يظهر خطأ في قاعدة البيانات بعد شهر**:
  غالباً انتهت مهلة *Test Mode* في Firestore (30 يوماً). راجع قسم *إعداد Firebase* وتأكد من نشر قواعد [`firestore.rules`](./firestore.rules).
- **الموقع يعرض تحديات مختلفة عن قاعدة البيانات التي أنشأتها**:
  تحقق من قيمة `VITE_FIREBASE_DATABASE_ID`؛ اتركها فارغة تماماً إذا كانت قاعدة البيانات لديك باسم `(default)`.
- **تعذر تشغيل الأغنية في التحدي**:
  تأكد أن الرابط مباشر وينتهي بملف صوتي مدعوم (`.mp3` / `.m4a` / `.ogg`) ويبدأ بـ `https://`، مثل روابط Cloudinary المباشرة، وليس رابط صفحة ويب.
- **التعديلات الجديدة لا تظهر بعد النشر رغم تحديث Vercel**:
  بسبب تخزين المتصفح أو Service Worker مؤقتاً، جرّب تحديث الصفحة بقوة (`Ctrl + Shift + R` أو إغلاق التطبيق المثبّت وإعادة فتحه). وفي حال تعديل `sw.js` مستقبلاً، غيّر رقم الإصدار في `CACHE_NAME` (مثل `sahra-molaa-v2`).
